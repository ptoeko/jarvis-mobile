# JARVIS Mobile — реестр замечаний, вложения и резервная копия, версия 0.4.0

Персональный помощник инженера для Android. Версия 0.4.0. Два варианта установки из одного кода: **APK** (Android-приложение) и **веб-приложение** (PWA). Инструкция по установке — [INSTALL.md](INSTALL.md).
ИИ **не подключён**. Ответы в диалоге — заранее заданные тексты с пометкой «Демо». Разбор заметок выполняется **по правилам, это не ИИ**.

## Что есть

**Этап 1:** экраны «Диалог», «Реестр», «Настройки», «Статус»; сохранение на устройстве (IndexedDB); удаление всей истории; установка на главный экран; запуск без интернета; тёмная и светлая темы.

**Этап 2:**
- Кнопка «В реестр»: заметка сохраняется в диалоге, по ней создаются черновики записей. Несколько заметок в одном сообщении разделяются пустой строкой (не более 20).
- Разбор по правилам — только явно написанное: дата (`23.10.2026`, `23.10.26`; несуществующие даты отбрасываются), оси (`ось 3/Б`, `в осях А–В/1–4`), отметки (`отм. +6.000`, `на отметке −0,300`, первая отметка без слова), помещения (`пом. 2.15`), нормы и пункты (`СП …`, `ГОСТ Р …`, `п. 5.3.2`), листы (`лист 12`), срок (`срок до …`, `устранить до …`), поля с метками (`Объект:`, `Вид работ:`, `Подрядчик:` / `отв.:` / `Исполнитель:`, `Статус:`, `Замечание:`). Остальное — «Не указано». «Описание» — полный текст заметки, если нет метки «Замечание:».
- «Статус» без метки `Статус:` всегда «Не указано».
- Каждый черновик проверяется и подтверждается человеком («Добавить в реестр» / «Отклонить»). Без подтверждения в реестр ничего не попадает.
- Номер присваивается при подтверждении и больше не меняется. Удаление записи не перенумеровывает остальные; номера удалённых записей не используются повторно.
- Исходный текст заметки хранится отдельно и не редактируется.
- Редактирование и удаление записи (с подтверждением) на экране «Реестр».
- Экспорт CSV с предварительным итогом: UTF-8 с BOM, разделитель `;`, строки CRLF, все значения в кавычках, переносы строк внутри ячеек, защита от формул.

## Данные

Схема IndexedDB не менялась: база `jarvis-mobile` версии 1, хранилища `messages`, `records`, `meta` с ключом `id`. Обновление с 0.1.0 сохраняет историю (проверяется тестом `upgrade_from_stage1`).

Запись реестра:

```
id, number (целое), date, object, location, workType, description, requirement,
responsible, deadline, status, sourceText (не изменяется), sourceMessageId,
createdAt, updatedAt
```

Счётчик номеров — `meta.nextRecordNumber`. Удаление всей истории очищает реестр и начинает нумерацию с 1.

## Защита CSV от формул

Перед значением ставится апостроф `'`, если первый значимый символ — `=`, `+`, `-`, `@` (в том числе полноширинные варианты), даже если перед ним стоят пробелы, неразрывные пробелы, невидимые символы, BOM или управляющие символы. Апостроф ставится также, если значение начинается с табуляции или перевода строки.

Исключение — значение, которое целиком является числом со знаком: `+6.000`, `-0.300`, `-0,300`, `-5`. Такие значения не изменяются. Число с пробелом или с любым другим текстом защищается. Последствие: текст вида `- нет обмазки` в начале ячейки выгружается как `'- нет обмазки`.

## Известные ограничения

- **Excel и LibreOffice сами определяют тип ячеек CSV.** При обычном открытии с русскими настройками LibreOffice превращает `№` в число, даты — в значения даты, а отметки с запятой (`-0,300`, `+12,450`) — в числа, теряя нули и знак «+». Отметки с точкой (`+6.000`) остаются текстом. Точный результат даёт импорт с форматом столбцов «Текст». В Excel поведение не проверялось. Полностью это решается только форматом XLSX.
- Резервной копии и импорта нет: данные живут только на одном телефоне. CSV — выгрузка для чтения, обратно не загружается.
- Разбор по правилам не понимает смысл. Например, «оси 3 и 4» даёт только «оси 3». Все поля нужно проверять глазами.
- Скачивание файла из установленного приложения на Android автоматически не проверялось — только в Chromium.

## Новое в 0.4.0

- **Вложения:** кнопка-скрепка в «Диалоге». Фото, видео (до 300 МБ), Word, PDF, Excel (до 25 МБ), не больше 10 файлов в сообщении. В APK можно снять фото или видео камерой — снимок пишется во внутреннюю папку приложения, разрешение на камеру не нужно. Файлы хранятся в IndexedDB (хранилище `attachments`, база версии 2) и открываются приложениями телефона. Без ИИ содержимое файлов не анализируется.
- Файлы заметки, отправленной «В реестр», прикладываются к каждому черновику и записи. CSV не менялся (11 столбцов).
- **Копирование текста:** значок у каждого сообщения (в APK — системный буфер обмена), выделение долгим нажатием.
- **Резервная копия:** Настройки → «Сохранить копию» — один ZIP без сжатия: `manifest.json` (сообщения, записи, черновики, служебные данные, список файлов с размером и CRC-32) и папка `files/`. Открывается и на компьютере.
- **Восстановление:** проверяется весь файл (формат, версия, номера записей без повторов, исходный текст, ссылки на файлы, контрольные суммы), показывается итог, после подтверждения данные заменяются одной транзакцией. При любой ошибке данные на телефоне не меняются.
- Большие файлы не читаются в память целиком: CRC по частям, в Android файл передаётся частями по 512 КБ.
- В APK на экране «Настройки» хранилище называется «В памяти приложения».

## Исправления в 0.3.1 (ревью 0.3.0)

- Сборка в GitHub падала: тест обновления искал git-метку `v0.1.0-stage1`, которой нет в репозитории. Теперь используется номер коммита.
- Черновики хранятся в базе (`meta.pendingDrafts`) и не пропадают, если Android закрыл приложение в фоне. Правки сохраняются через 0,4 с и сразу при сворачивании.
- Подтверждение записи — одна транзакция: запись, счётчик номеров и удаление черновика. При сбое не остаётся записи без счётчика и подтверждённого черновика (иначе возможен дубль).
- Экспорт на Android: содержимое файла хранится во внутренней папке приложения, пока открыто окно «Сохранить». Раньше, если система закрывала JARVIS в этот момент, файл сохранялся пустым без сообщения.
- Подпись APK: постоянный ключ для обеих сборок и проверка его отпечатка. Раньше без секретов каждая сборка подписывалась новым случайным ключом, и обновление требовало удалить приложение вместе с данными.
- Выпуск: постоянная ссылка `releases/latest/download/JARVIS-Mobile.apk`.

## APK (Android-приложение)

Папка `android/` — оболочка на стандартном Android WebView, без сторонних библиотек (`MainActivity.java`).

- Файлы веб-приложения копируются внутрь APK при сборке и открываются по адресу `https://appassets.androidplatform.net`. Это не сервер: оболочка перехватывает каждый запрос и отдаёт файл из APK, а все остальные адреса блокирует (ответ 403 и политика безопасности страницы `connect-src 'self'`).
- Данные хранятся в IndexedDB во внутренней памяти приложения. Облачная резервная копия отключена (`allowBackup=false`, `data_extraction_rules.xml`).
- Экспорт CSV идёт через мост `window.JarvisAndroid.saveTextFile` и системное окно «Сохранить» (`ACTION_CREATE_DOCUMENT`), без разрешений на доступ к памяти.
- Кнопка «Назад» сначала закрывает открытое окно, затем возвращает к предыдущему экрану, затем выходит из приложения.
- minSdk 24 (Android 7), targetSdk 34. При устаревшем системном WebView приложение показывает, что нужно обновить.
- Версия APK берётся из `APP_VERSION` в `js/core/config.js`.

Сборка APK в этой среде разработки невозможна: нет Android SDK, а источники для его загрузки закрыты. APK собирается в GitHub Actions (`.github/workflows/build.yml`):

1. Тесты веб-приложения: модульные и сквозные в Chromium, включая LibreOffice.
2. Сборка отладочного и подписанного APK, проверка подписи (`apksigner verify`).
3. Эмулятор Android 14. На отладочном APK через протокол отладки WebView проходит сценарий: заметка → черновики → подтверждение → удаление без перенумерации → перезапуск (записи и непроверенный черновик на месте) → кнопка «Назад» → экспорт CSV через системное окно «Сохранить» с проверкой содержимого файла → повторный экспорт в режиме «Не сохранять действия» (система закрывает JARVIS, пока открыто окно «Сохранить»). Подписанный APK устанавливается поверх тестовой версии с данными (как обновление на телефоне) — запись должна сохраниться, затем проверяется запуск с нуля. Скриншоты сохраняются в артефактах сборки.
4. Выпуск подписанного APK на странице Releases (тег `v<версия>`) — только если все проверки прошли.
5. Публикация веб-версии на GitHub Pages.

Секрет репозитория для подписи: `ANDROID_KEYSTORE_BASE64` (пароль и имя ключа по умолчанию — `jarvis-mobile` и `jarvis`, можно переопределить секретами `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`). Без него собирается только тестовая версия, а выпуск не создаётся. Отпечаток сертификата — `android/signing-certificate-sha256.txt`; сборка с другим ключом завершается ошибкой.

Сборка запускается и для веток `claude/**` (проверка до слияния), выпуск и веб-версия — только для `main`. При ошибке причина выводится в аннотациях на странице сборки (`.github/scripts/run.sh`).

`tests/e2e/test_apk_mode.py` проверяет веб-часть в условиях APK: тот же адрес, те же заголовки безопасности из `MainActivity.java`, блокировка внешних адресов, имитация моста сохранения.

## Публикация веб-версии

GitHub Pages публикуется из GitHub Actions (задача `pages`), в публикацию попадают только файлы приложения. При изменении файлов приложения увеличивать `APP_VERSION` в `js/core/config.js` и `VERSION` в `sw.js` (тест проверяет их совпадение), а новые файлы добавлять в список `SHELL` в `sw.js` (тоже проверяется тестом).

Контрольная копия этапа 1 — коммит `adaddbc` (git-тег `v0.1.0-stage1` в локальной копии).
