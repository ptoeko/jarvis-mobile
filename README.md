# JARVIS Mobile — этап 1 (каркас приложения)

Персональный помощник инженера в виде PWA для Android. Версия 0.1.0.
Работает **только в демонстрационном режиме**: ИИ не подключён, ответы — заранее заданные тексты с пометкой «Демо».

## Что есть на этапе 1

- Экраны «Диалог», «Реестр», «Настройки», «Статус» с нижней панелью вкладок.
- Диалог: ввод текста, проверка ввода (пусто, длина до 4000 символов, управляющие символы), демо-ответы, команды «помощь» и «статус».
- Сохранение истории на устройстве (IndexedDB), запрос у браузера защиты данных от автоочистки.
- Удаление всей истории с подтверждением.
- Реестр: пустая таблица с утверждаемой схемой из 11 полей. Записи не создаются до этапа 2.
- Экран «Статус» правдиво показывает, что работает, что в демо-режиме и что запланировано.
- Установка на главный экран (manifest, иконки), запуск без интернета (service worker).
- Тёмная и светлая темы по настройке телефона, адаптация под экран Android, крупные кнопки.

Не реализовано намеренно: разбор заметок и экспорт (этап 2), кнопка микрофона в приложении (этап 3), подключение ИИ (этап 4).

## Безопасность и данные

- В коде нет ключей и секретов; автоматический тест проверяет это при каждом запуске.
- Приложение не обращается ни к одному внешнему серверу (тоже проверяется тестом).
- Будущий ИИ подключается только через серверный посредник с авторизацией, ограничением частоты и расходов (`js/core/ai.js` сейчас всегда возвращает «не подключено»).
- Пользовательский текст выводится только как текст (`textContent`), HTML из сообщений не исполняется.
- Используются только учебные данные.

## Отклонение от архитектурного документа

В документе предлагались React + Vite, Zod и SheetJS. В среде разработки доступ к реестру пакетов npm закрыт политикой безопасности, поэтому каркас написан на **обычном JavaScript без сборки и без внешних зависимостей**. Для этапа 1 это упрощение: нет шага сборки, нет сторонних библиотек, файлы публикуются как есть. Для экспорта XLSX на этапе 2 потребуется либо собственный небольшой модуль, либо доступ к библиотеке — решение принять при планировании этапа 2.

## Структура

```
index.html               разметка экранов
css/app.css              оформление
js/app.js                связь интерфейса и логики
js/core/config.js        версия, схема реестра, «Не указано»
js/core/validate.js      проверка ввода
js/core/demo.js          демо-ответы
js/core/store.js         хранилище (поверх адаптера)
js/core/idb.js           адаптер IndexedDB
js/core/status.js        сводка «что работает»
js/core/ai.js            точка подключения ИИ (не подключено)
sw.js                    офлайн-кеш файлов приложения
manifest.webmanifest     установка на главный экран
tests/unit               модульные тесты (node --test)
tests/e2e                сквозные тесты в Chromium (Playwright, экран Pixel 7)
```

## Тесты

```
npm test                         # 25 модульных тестов, нужен Node.js 20+
python3 tests/e2e/test_app.py    # 16 сквозных тестов, нужен Python-пакет playwright с Chromium
```

Последний прогон перед передачей: 25 из 25 и 16 из 16 пройдено (22.10.2026).
Сквозные тесты проверяют: демо-режим и подписи ответов, ошибки ввода, Enter для отправки, вывод HTML как текста, сохранение после перезагрузки, вкладки и кнопку «Назад», пустой реестр, честность экрана «Статус», отмену и подтверждение удаления истории, запуск без интернета, отсутствие горизонтальной прокрутки на экране 360 px, размер кнопок, manifest и иконки.

Тесты **не** заменяют проверку на реальном телефоне: микрофон клавиатуры, установка на главный экран и поведение конкретного Android проверяются владельцем.

## Публикация

GitHub Pages из ветки `main`, папка `/ (root)`. Сборка не нужна. При изменении файлов приложения увеличивать `APP_VERSION` в `js/core/config.js` и `VERSION` в `sw.js` (тест проверяет их совпадение).
