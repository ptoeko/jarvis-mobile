# Ревью JARVIS Mobile 0.3.0 → исправления 0.3.1

Дата: 25.10.2026. Проверено: исходный код (`js/`, `android/`, `sw.js`, `.github/workflows/build.yml`), все тесты, реальная сборка APK в GitHub Actions и сценарий на эмуляторе Android 14.

## Критические

| # | Проблема | Что изменено | Чем подтверждено |
|---|----------|--------------|------------------|
| К1 | Сборка в GitHub падала на сквозных тестах: тест обновления искал git-метку `v0.1.0-stage1`, которой нет в репозитории. APK не собирался вообще. | Тест берёт старую версию по номеру коммита (`OLD_VERSIONS` в `tests/e2e/test_stage2.py`). | Сборка в GitHub Actions: все задания зелёные. |
| К2 | Без секретов каждая сборка подписывалась новым случайным ключом. Обновление поверх установленной версии невозможно → пришлось бы удалить приложение, а с ним и все данные (резервная копия отключена). | Постоянный ключ из одного секрета `ANDROID_KEYSTORE_BASE64`; им подписываются обе сборки. Отпечаток сертификата в `android/signing-certificate-sha256.txt` — сборка с другим ключом завершается ошибкой. | Шаг «Проверка APK и подписи»; на эмуляторе режим `update`: подписанный APK ставится поверх тестовой версии с записью, запись должна остаться (запускается, когда задан секрет). |

## Существенные

| # | Проблема | Что изменено | Чем подтверждено |

| С1 | Непроверенные черновики жили только в памяти. Android закрывает приложение в фоне (камера, звонок) — черновики и правки пропадали. | Черновики хранятся в базе (`meta.pendingDrafts`, схема не менялась). | С2 | Экспорт на Android: если система закрывала JARVIS, пока открыто окно «Сохранить», файл создавался пустым, без сообщения. | Содержимое файла хранится во внутренней папке приложения до записи; результат показывается системным сообщением, если страница перезапускалась. | Эмулятор: повторный экспорт в режиме «Не сохранять действия» — файл совпадает с первым байт в байт. |

## Косметические и замечания к тестам

- Нестабильные тесты (гонки «перезагрузка раньше сохранения»): `opens_without_internet`, `delete_history_cancel_then_confirm`, `upgrade_from_stage1`, `no_horizontal_scroll_with_drafts_and_records` — исправлены ожиданием результата.
- При ошибке сборки причина выводится в аннотациях на странице сборки (`.github/scripts/run.sh`).
- Публикация веб-версии не помечает сборку неудачной, если GitHub Pages не включён.
- Версия в `package.json` и описание страницы приведены в соответствие.
- Не исправлено (не влияет на работу): предупреждения GitHub об устаревших версиях действий (Node.js 20, setup-java v4).

## Проверено без замечаний

- Сохранение записей после перезапуска — `records_and_numbering_survive_restart`, эмулятор.
- Исходный текст хранится дословно и не редактируется — модульный `исходный текст хранится дословно…`, `updateRecord` отклоняет `sourceText`.
- Каждая запись только после подтверждения человеком — черновики не попадают в реестр (`черновики сохраняются… не попадают в реестр`).
- Статус «Не указано» без метки «Статус:» — модульный и сквозной `status_not_specified_in_table`.
- Нумерация не меняется при удалении и после перезапуска, номера не повторяются.
- Защита CSV от формул: `=`, `+`, `-`, `@`, полноширинные, с пробелами/невидимыми символами впереди, табуляция и перевод строки — апостроф; числа со знаком (`+6.000`) не изменяются.
- Миграция IndexedDB: обновление с 0.1.0 и с 0.3.0 (`upgrade_from_030`: записи, номера, сообщения на месте, схема версии 1 без изменений).
- Экран Android: нет горизонтальной прокрутки на 360 px, кнопка «Назад» закрывает окна.

## Чего нет в 0.3.0 (не ошибка, а отсутствующая функция)

- **Импорта CSV нет** — проверять нечего. CSV служит только выгрузкой.
- **Резервной копии и восстановления нет.** Данные живут на одном телефоне; при потере телефона или удалении приложения они теряются. Это главный оставшийся риск.
